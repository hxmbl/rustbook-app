# The desktop app

A Tauri v2 shell around *The Rust Programming Language*. It ships the book's
source, theme and an `mdbook` binary, and runs `mdbook serve` on a loopback port
when it starts. Nothing is rendered at build time: the HTML you read is built by
mdbook in the app's cache directory on launch.

Linux is the target for now: `cargo tauri build` produces a `.deb` and an
AppImage. The code is portable, but macOS and Windows have not been tried.

## What is in it

| Path | What it is |
| --- | --- |
| `scripts/stage.sh` | Copies the book source and the three binaries into `src-tauri/resources/` |
| `src-tauri/src/lib.rs` | Creates the window, starts the server, opens external links in the browser |
| `src-tauri/src/server.rs` | Copies the book to the cache, runs `mdbook serve`, waits for HTTP 200, stops it on exit |
| `src-tauri/src/paths.rs` | Finds the bundled resources, in a bundle and under `tauri dev` |
| `ui/index.html` | The loading page, and the page that shows a startup failure |
| `src-tauri/resources/` | Generated by `scripts/stage.sh`; not committed |

## Prerequisites

```sh
cargo install tauri-cli --version "^2"
cargo install mdbook --version 0.5.1 --locked
```

The app itself does not need Rust or mdbook at runtime; both are only used to
produce the bundle. `scripts/stage.sh` looks for `mdbook` on `PATH`, then in
`~/.cargo/bin`, and `MDBOOK_BIN` overrides both. It refuses any version other
than 0.5.x, because the book's configuration and preprocessors are pinned to the
version CI uses.

Linux also needs the usual Tauri dependencies (WebKitGTK 4.1, GTK 3, librsvg),
as described in the [Tauri prerequisites].

[Tauri prerequisites]: https://v2.tauri.app/start/prerequisites/

## Running

From this directory:

```sh
cargo tauri dev
cargo tauri build            # .deb and AppImage under src-tauri/target/release/bundle
```

Both commands run `scripts/stage.sh` first (`beforeDevCommand` /
`beforeBuildCommand`), so a fresh clone needs no setup step. If you run plain
`cargo build` in `src-tauri`, run the script yourself first.

## How a launch works

1. `setup` creates the window with the loading page in `ui/`.
2. A background thread copies `resources/book-source` to
   `$XDG_CACHE_HOME/dev.hxmbl.rustbook/book` (about 11 MB, a few dozen
   milliseconds). Installed resources are read-only and mdbook needs somewhere
   to write, so this copy is unavoidable; doing it on every launch means an app
   update can never serve a stale book.
3. The same thread copies `mdbook`, `mdbook-trpl-note` and `mdbook-trpl-listing`
   into `<cache>/book/bin` and makes them executable. The staged `book.toml`
   runs the preprocessors as `bin/mdbook-trpl-note`, relative to the book root,
   so no absolute paths have to be generated.
4. It picks a free loopback port and runs
   `mdbook serve <cache>/book --hostname 127.0.0.1 --port <port> --dest-dir <cache>/book/book`.
   mdbook's output goes to `<cache>/mdbook.log`.
5. It polls `GET /` until it gets a 200, then navigates the window to the
   server. If mdbook exits or never answers, the loading page is replaced with
   the error and the log path.
6. On exit the mdbook process is killed. A second launch focuses the existing
   window instead of starting a rival server over the same cache directory.

The book's own links to other sites are opened in the user's browser rather than
replacing the book in a window that has no back button.

## Why the binaries are resources, not sidecars

Tauri's `externalBin` sidecars are installed next to the app binary — on Linux
that means `/usr/bin/mdbook`, `/usr/bin/mdbook-trpl-note` and so on. A package
that owns `/usr/bin/mdbook` conflicts with a real mdbook installation, and
overwriting someone's toolchain is not a reasonable thing for a book reader to
do.

As resources they live in `/usr/lib/Rust Book/resources/` (or
`Contents/Resources/resources/` in a macOS app), where they cannot collide with
anything. The app copies them into its cache at launch and sets the executable
bit, which packaging does not preserve.

## Updating the book

The book is a copy, not a link. After pulling changes to `src/` or `listings/`,
run `cargo tauri dev` (or `scripts/stage.sh`) again; the cache is refreshed on
every launch, so the new text appears immediately.
